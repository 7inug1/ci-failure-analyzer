# 런타임 비교: Node.js와 Express 대 Bun (2026-11-19)

멘토링 2회차 숙제. 같은 서버 코드(`analyzer/src/server.ts`, Express 5, multer)를 Node.js와 Bun으로 각각 실행해 비교했다.

## 결과 (5회 측정의 중앙값)

| 항목                               | Node.js v20.19.5 | Bun 1.4.4  | 비고                       |
| ---------------------------------- | ---------------- | ---------- | -------------------------- |
| 시작 시간(ms)                      | 213              | 131        | Bun이 약 38% 빠름          |
| 메모리, 켠 직후(MB)                | 81.2             | 50.2       | Bun이 약 38% 적음          |
| 메모리, 부하 후(MB)                | 120.7            | 102.7      |                            |
| `/fingerprint` 초당 요청 수        | 2,395            | 2,548      | 차이 약 6%, 측정 오차 범위 |
| `/fingerprint` p50 / p95(ms)       | 7.1 / 14.4       | 7.3 / 13.0 | 사실상 같음                |
| `/fingerprint` 오류 수             | 0                | 0          |                            |
| 5명 동시 `/analyze` 전체 시간(ms)  | 2,027            | 2,021      | 가짜 AI 지연 2,000ms 포함  |

원본 값은 `runtime-benchmark-node.json`, `runtime-benchmark-bun.json`.

## 읽는 방법

- **서버가 하는 일은 매우 빠르다.** AI를 부르지 않는 `/fingerprint`(로그 정리, 비밀값 가리기, 에러 구간 추출)가 한 요청에 약 7ms다. 실제 AI 응답은 4~12초(서버 로그)라서 서버 처리는 전체의 0.1% 수준이다.
- **동시 사용에서 서버는 병목이 아니다.** 가짜 AI가 2초를 쓰는 요청 5개를 동시에 보내도 전체가 약 2.03초에 끝났다(한 명일 때와 같다). 서버가 AI 응답을 기다리는 동안 다른 요청을 받는 비동기 방식이라서다. 20명이어도 같았다.
- **그래서 실제 병목은 AI 응답 대기와 호출 한도다.** CI 러너가 분석 서버의 응답을 기다리는 구간(다이어그램 7번)이 곧 CI 시간이므로, 서버가 아니라 AI 호출 시간과 시간 제한(타임아웃)이 중요하다. 여러 명이 동시에 쓰면 서버보다 무료 모델의 호출 한도(멘토 가이드에는 분당 20회라고 적혀 있다)를 먼저 넘을 수 있고, 이때는 429로 받아 안내 댓글을 남기도록 구현해 두었다(실제 429 상황은 시험하지 않았다).
- Bun은 시작 시간과 메모리에서 이긴다. 하지만 이 서버는 한 번 켜 두고 오래 쓰는 작은 서버라 그 차이가 체감되지 않는다.

## 측정 방법과 한계

- **같은 서버 코드, 같은 입력.** 입력은 실제 실패 CI 로그(3.7KB)와 리포트(6.8KB)다.
- **가짜 AI 서버.** `bench/mock-llm.mjs`가 2,000ms 뒤에 올바른 모양의 답을 돌려준다. 실제 OpenRouter의 지연, 네트워크, 호출 한도는 반영되지 않았다. 서버에는 환경 변수 `OPENROUTER_BASE_URL`로 이 가짜 서버를 연결했다(기본값은 OpenRouter).
- **같은 맥 한 대, 루프백 통신.** 네트워크 지연이 없다. 측정 도구와 서버가 같은 컴퓨터에서 돌아 서로 영향을 줬을 수 있다.
- **Node는 `tsx`로 TypeScript를 변환해 실행하고, Bun은 TypeScript를 직접 실행한다.** 시작 시간에는 이 차이가 들어 있다. 서버를 미리 JavaScript로 빌드해 Node로 실행하면 Node의 시작 시간은 달라질 수 있다(시험하지 않았다).
- Node는 v20.19.5(`.nvmrc` 기준)다. 더 새 버전의 Node에서는 결과가 다를 수 있다.
- 요청 본문이 작다(약 10KB). 로그가 수 MB가 되는 경우는 시험하지 않았다. 서버는 업로드를 5MB로 제한한다.
- `/fingerprint` 속도는 측정 중 다른 프로그램의 영향을 받을 수 있어 5~6% 차이는 의미가 없다고 본다.

## 다시 측정하는 방법

```bash
cd analyzer
node bench/bench.mjs node 5   # 5회 측정
node bench/bench.mjs bun 5    # Bun 필요: brew install bun
```
