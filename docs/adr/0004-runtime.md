# 0004. 분석 서버의 실행 환경(런타임)

상태: 결정됨 (2026-11-19)

## 배경

멘토링 2회차 숙제: 분석 서버를 Node.js와 Express로 할지 Bun으로 할지 비교하고 선택 이유를 말할 수 있어야 한다.
언어(JavaScript와 TypeScript)는 ADR 0003에서 정했다.

## 결정

**Node.js와 Express를 유지한다.** (TypeScript 실행은 개발 중 `tsx`를 쓴다.)

## 이유

- 같은 코드를 두 런타임에서 재서 비교했다(`docs/eval/runtime-benchmark.md`). Bun은 시작 시간(131ms 대 213ms)과 메모리(50MB 대 81MB)에서 낫지만, 서버가 하는 일의 속도와 동시 사용(5명, 20명)에서는 차이가 없었다.
- 이 서버는 AI 응답을 기다리는 시간이 대부분이다(서버 처리 약 7ms, AI 응답 4~12초). 그래서 런타임을 바꿔도 전체 시간이 거의 달라지지 않는다. 병목은 런타임이 아니라 AI 호출 시간과 호출 한도다.
- CI와 러너, 테스트가 이미 Node 기준이다(`.nvmrc`, `setup-node`, 서버 테스트의 `node --test`). Bun을 쓰면 러너 맥과 CI에 도구를 하나 더 설치하고 관리해야 한다.
- 멘토 가이드가 Node.js와 Express 기준이다.

## 버린 대안

- **Bun과 Express:** 같은 코드가 그대로 돌아가는 것은 확인했다(호환 문제 없음). 이득이 이 서버에서는 의미가 없어 도입 비용을 치를 이유가 없다.
- **Bun 내장 서버나 Hono 같은 다른 프레임워크:** 코드를 다시 써야 해서 이번 비교에서는 시험하지 않았다.

## 결과

- 필요해지면 코드 변경 없이 `bun src/server.ts`로 실행할 수 있어 나중에 바꾸는 비용이 낮다.
- 더 새로운 Node 버전, 큰 로그(수 MB), 실제 OpenRouter 지연을 포함한 시험은 하지 않았다. 그런 조건에서 병목이 달라지면 이 결정을 다시 본다.
