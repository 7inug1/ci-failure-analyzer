# 시나리오 정답표

AI 분석이 맞았는지 채점할 때 쓰는 정답입니다. AI의 답을 보기 전에 작성했습니다.

| 시나리오 | 패치 파일                                       | 원인                                                                              | 고칠 파일       | 실제 실패 문구                                                   |
| -------- | ----------------------------------------------- | --------------------------------------------------------------------------------- | --------------- | ---------------------------------------------------------------- |
| S1       | `patches/discount-floor-instead-of-round.patch` | 할인 결과를 반올림(`Math.round`)하지 않고 내림(`Math.floor`)해서 904.5가 904가 됨 | `src/price.js`  | `Expected: 905`, `Received: 904` (테스트 1개 실패)               |
| S2       | `patches/cart-export-name-typo.patch`           | `cart.js`가 내보내는 함수 이름을 `lineLable`로 잘못 적음                          | `src/cart.js`   | `TypeError: lineLabel is not a function` (테스트 3개 실패)       |
| L1       | `patches/format-drops-won-suffix.patch`         | `format.js`가 금액 뒤의 `원`을 빼먹어서, 이 함수를 쓰는 모든 테스트가 실패함      | `src/format.js` | `Expected: "9,000원"`, `Received: "9,000"` 등 (테스트 12개 실패) |

## 채점 방법

시나리오마다 AI의 PR 댓글(또는 이슈)을 아래 3칸으로 정답표와 비교해 O 또는 X로 적는다.

| 칸        | O로 보는 기준                                                                        |
| --------- | ------------------------------------------------------------------------------------ |
| 원인      | AI의 "추정 원인"이 정답 원인과 같은 뜻이다. 표현은 달라도 된다.                      |
| 고칠 파일 | AI가 정답 파일을 한 번이라도 짚었다. 원인 설명과 "다음에 확인할 곳" 어디든 상관없다. |
| 실패 문구 | AI가 인용한 실패 내용이 실제 실패 로그와 같고, 지어낸 내용이 없다.                   |

판정은 이렇게 한다.

- **일치:** 3칸이 모두 O (L1은 "여러 곳이 실패하지만 원인은 한 곳"으로 묶어 설명해야 원인을 O로 본다)
- **일부 일치:** 원인과 고칠 파일 중 하나만 O
- **불일치:** 원인이 X
- **호출 실패:** AI 호출이 실패해 안내 댓글만 달림. 채점에서 제외하고 결과표에 사유를 적는다.

프로젝트 통과 기준은 **시나리오 3개 중 2개 이상 "일치"** 이다 (기획서의 "마지막 전체 확인" 2번, 제안한 기준).
AI의 답을 본 뒤에는 이 기준을 바꾸지 않는다.
